# 2.1 — The `lending` module

**Parent:** [§2.1](../phase-2-lending-checkout.md) · **Depends on:** 2.0 ·
**Unblocks:** 2.3a, 2.4b
**Estimate:** 1.5 d · **Risk:** high — this is the custody record

## Goal

`loans` and the operations over it, with the two database constraints that make
"a device is in exactly one person's hands" true by construction rather than by
convention. `lending` never learns what a user or a device *is*: it receives
UUIDs and returns rows. That is what keeps it extractable (NFR-17) and what the
depguard `lending-isolation` rule enforces.

## Design notes

**Two constraints, two error codes, two messages** ([ADR-0008](../../adr/0008-temporal-custody-constraint.md)):

| Constraint | Code | Mapped to | Human message |
|---|---|---|---|
| `loans_one_open_per_device_uk` | `23505` | `ErrDeviceAlreadyOnLoan` | "Already taken by a colleague in Radiology" |
| `loans_no_overlapping_custody` | `23P01` | `ErrOverlappingCustody` | "Already recorded as out to someone else on those dates" |

The exclusion constraint subsumes the unique index (an open loan is
`[borrowed_at, ∞)`), and is kept alongside it purely so the live path and the
backfill path fail with distinguishable codes. Do not "simplify" by dropping one.

**Both typed errors carry the conflicting loan**, not just a message —
`ErrDeviceAlreadyOnLoan` needs the current holder so the kiosk can say who has
it, and `ErrOverlappingCustody` needs the whole conflicting row so the backfill
screen can offer resolutions. Model them as structs implementing `error` with an
`Is` target, so `errors.Is(err, lendingapi.ErrDeviceAlreadyOnLoan)` still works:

```go
type DeviceAlreadyOnLoanError struct{ Existing Loan }
func (e *DeviceAlreadyOnLoanError) Error() string { … }
func (e *DeviceAlreadyOnLoanError) Is(target error) bool { return target == ErrDeviceAlreadyOnLoan }
```

**`'[)'` range bounds** mean returned-at-10:00 and re-borrowed-at-10:00 is not a
conflict. The `CHECK (returned_at > borrowed_at)` is what stops a zero-length
range — which overlaps nothing — from slipping past the exclusion constraint.
Both facts get a named test.

### 2.1.4 Service

- [x] `OpenLoan(ctx, deviceID, userID string, dueAt *time.Time, meta OpenMeta)`
      — `meta` carries kiosk id, actor, source, `condition_out`, `session_id`,
      **plus `BorrowedAt time.Time`** (not in the original field list): an
      optional override of the clock, valid only within a few seconds of now
      — otherwise `ErrBackdatedNotPermitted`. Needed to give
      `TestOpenLoanRejectsBackdatedBorrowedAt` (listed under this sub-phase's
      own tests) something on `OpenLoan` to actually reject; without it the
      signature had no way to receive a backdated value at all
- [x] `CloseLoan(ctx, loanID string, meta CloseMeta)` — captures `condition_in`,
      `return_actor`, `return_source`, `return_kiosk_id`
- [x] `OpenLoansFor(userID)`, `HolderOf(deviceID)`, `OverdueLoans(asOf)`
- [x] `ForceReturn(loanID, reason, conditionIn string, returnedAt *time.Time, actor)`
      — reason mandatory, `returnedAt` optional and validated against
      `borrowed_at` (by `loans_return_after_borrow`, surfaced as
      `ErrInvalidReturnTime`)
- [x] `WriteOff(loanID, reason, actor)` — sets `written_off`, which drops the row
      out of the exclusion constraint's predicate; that is intentional and
      documented in the code. **Also sets `returned_at`**: `loans_status_matches_return`
      requires it for *any* non-open status, not just `returned` — easy to miss
      since the parent doc's CHECK is stated but this consequence isn't spelled out
- [x] `RecordHistorical(ctx, params)` — the only path that accepts a past
      `borrowed_at`; every other write takes its timestamp from the clock
- [x] `DueDateFor(category catalogapi.Category, borrowedAt)` — **no**: the
      category is passed *in* as a `*time.Duration`, because `lending` may not
      import `catalogapi`. `checkout` reads the category and hands over the
      period. Nil period ⇒ nil `due_at`
- [x] `translateLoanErr` mapping `23505` → `DeviceAlreadyOnLoanError` (re-reading
      the existing open loan to populate the holder), `23P01` →
      `OverlappingCustodyError` (re-reading the conflicting row), `23514` →
      the specific `CHECK` violated, `pgx.ErrNoRows` → `ErrLoanNotFound`.
      The re-reads run against the plain pool (`lendingstore.New(s.pool.Pool)`),
      never `db.Conn(ctx, s.pool)` — by the time translation runs, the
      transaction that produced the error is already rolled back, so reusing
      its context would fail every time
- [x] `origin` is write-once: no update statement includes it (INV-15)
- [x] Audit events on every mutation, in the caller's transaction

## Risks

| Risk | Mitigation |
|---|---|
| The exclusion constraint is dropped later "because the unique index covers it" | ADR-0008 plus `TestINV13_OverlappingCustodyRejected`, which fails immediately if it goes |
| `written_off` rows escaping the constraint hides a real overlap | Documented in the migration and asserted: writing off then re-borrowing over the same period is allowed *by design*, and the test says so out loud |
| Holder lookup on the `23505` path re-reads inside a failed transaction | The re-read happens after rollback, on the pool, in the error translation path — covered by a test that asserts the holder is populated |
