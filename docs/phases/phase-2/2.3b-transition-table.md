# 2.3b — The transition table as data, and the message catalogue

**Parent:** [§2.3](../phase-2-lending-checkout.md) · **Depends on:** 2.3a ·
**Unblocks:** 2.3c, 2.4b (shares the resolution rules), 2.7
**Estimate:** 1 d · **Risk:** medium — cheap to get subtly wrong, cheap to test

## Goal

Turn [04](../../04-scanning-and-checkout-flows.md)'s tables into a Go data
structure that can be printed, diffed and exhaustively iterated — and separate
the *decision* (pure, no I/O) from the *execution* (transactional, in 2.3c).
This split is what makes the full matrix a fast unit test instead of 60
container-backed integration tests.

## Design notes

**Pure decision function:**

```go
// Decide is total: every (state, input) pair returns a Decision. It performs
// no I/O and takes no clock — the caller resolves the token and loads the
// subject first, then asks what to do about it.
func Decide(state SessionState, snap Snapshot, in Input) Decision
```

- `Input` — the *resolved* scan: `{Kind: device|user|unbound|unknown|revoked,
  DeviceID, DeviceStatus, HolderUserID, UserID, UserStatus, TokenPreview,
  SameAsPendingWithin3s bool}`
- `Snapshot` — the session as it stands: `{UserID, PendingDeviceID, LastScan…}`
- `Decision` — `{Action, NextState, ClearPending, MessageKey, MessageArgs}` where
  `Action ∈ {none, hold_device, replace_pending, set_user, switch_user, borrow,
  return, reject, duplicate, expire}`

**The table is a map, not a switch.** Declared as
`map[SessionState]map[InputClass]Rule`, with an `init()`-time completeness check
that every `(state × InputClass)` pair has a rule. A missing cell fails at
process start and in a unit test, which is the property [04](../../04-scanning-and-checkout-flows.md)
asks for ("a missing cell is a compile-time gap"). Where a genuine exhaustive-map
type is not expressible in Go, the completeness test is the enforcement.

**`InputClass`** is the row axis of the matrix, derived from `Input` by a small
pure classifier: `device_available`, `device_on_loan_same_user`,
`device_on_loan_other_user`, `device_unavailable`, `device_duplicate`,
`user_active`, `user_same`, `user_suspended`, `user_archived`, `unbound`,
`unknown`, `revoked`, `timeout`. Classification is itself table-tested — it is
where "same user" and "other user" are decided, and getting it wrong silently
turns a rejection into a return.

**One resolution rule, two callers.** `Decide`'s borrow-or-return judgement for
`device_on_loan_same_user` is the same question `ResolveHistorical` asks of a
past instant ([2.4b](2.4b-paper-backfill.md)). Factor the comparison into
`resolveAction(custodyHolderID, actorID) Action` so both paths call it and the
kiosk and the backfill screen cannot disagree (FR-74, and the reason
[04](../../04-scanning-and-checkout-flows.md) says the logic is shared).

**Messages are keys, not strings.** `Decision` carries `MessageKey` +
`MessageArgs`; rendering happens in a catalogue so wording changes ship without
a kiosk deploy (FR — the parent's "externalised into a message catalogue").

## Work items

### 2.3b.1 The table

- [ ] `internal/modules/checkout/internal/machine/state.go` — `SessionState`,
      `InputClass`, `Action` enums with `String()`
- [ ] `internal/modules/checkout/internal/machine/table.go` — the full table
      transcribed cell by cell from [04](../../04-scanning-and-checkout-flows.md),
      each row commented with the doc's wording
- [ ] `init()` completeness check panicking on a missing cell
- [ ] `classify(in Input, snap Snapshot) InputClass`
- [ ] `Decide(state, snap, in) Decision`
- [ ] `Table()` accessor returning the table for the 2.7 JSON export and for the
      admin console's future "why did it do that" view

Cells to transcribe, verbatim from the doc, including the ones easy to miss:

- From `idle`: a device on loan is **held**, not rejected — the rejection comes
  later, when the user turns out not to be the holder
- From `awaiting_user`: a *different* device **replaces** the pending one
- From `awaiting_device`/`ready`: a *different active user* closes the session
  and opens a new one — this is the only cell that produces two sessions
- Unbound/unknown/revoked from `awaiting_user` **release the pending device**
- Duplicate (< 3 s, same token) is `duplicate`, never a rejection

### 2.3b.2 Message catalogue

- [ ] `internal/modules/checkout/internal/messages/catalogue.go`: `map[MessageKey]Template`
      where `Template{Title, Detail string, Tone Tone}` and `Detail` is a
      `text/template` over `MessageArgs`
- [ ] Keys for every outcome, including the three refusals of
      [2.4](2.4-unrecognised-cards.md), each naming the paper fallback
- [ ] `Render(key, args) checkoutapi.Message`, with a test asserting **every**
      `MessageKey` produced by the table has a template — an unrendered key must
      be impossible, because the kiosk has no fallback wording
- [ ] Holder names appear only in in-session messages, never in error bodies
      ([06](../../06-api-contract.md): "keeps 'scan any device to learn who has
      it' from becoming a staff-location oracle")
- [ ] Tone mapping: borrow/return `success`, holds and identifications `info`,
      guidance refusals `warning`, faults `error`

### 2.3b.3 Timeout rules

- [ ] TTL per state as data in the same table (`awaiting_user` 45 s,
      `awaiting_device`/`ready` 25 s), so 2.7's JSON export carries them and the
      kiosk's XState config gets them from the same source

## Tests

All unit, all fast (`internal/modules/checkout/internal/machine`):
- [ ] `TestTableIsComplete` — every `(state × InputClass)` has a rule
- [ ] `TestMatrix` — the full grid from [04](../../04-scanning-and-checkout-flows.md#test-matrix)
      as named subtests, one per cell, asserting `Action` and `NextState`
- [ ] `TestClassify` — table-driven over every `InputClass`, including
      same-user vs other-user and the 3 s duplicate window boundary (2.999 s is a
      duplicate, 3.001 s is not)
- [ ] `TestPendingDeviceReleasedOnRefusal` — for each of unbound/unknown/revoked
- [ ] `TestEveryMessageKeyHasATemplate`
- [ ] `TestMessagesNeverContainRawTokens` — render every template with an args
      map containing a token-shaped value and assert it is not echoed
- [ ] `TestResolveActionSharedWithHistorical` — same helper, both call sites

## Exit criteria

- [ ] Every cell of [04](../../04-scanning-and-checkout-flows.md)'s matrix has a
      passing named test, and the table refuses to load with a cell missing
- [ ] `Decide` has no I/O, no clock and no database in its dependency graph —
      asserted by the package having no imports beyond the standard library and
      `checkoutapi`
- [ ] Every message the kiosk can receive comes from the catalogue, not from a
      string literal in a handler

## Risks

| Risk | Mitigation |
|---|---|
| The table and the doc drift | Each rule cites the doc line it came from; 2.9 re-reads [04](../../04-scanning-and-checkout-flows.md) against the table as a review step |
| "Just this once" conditional added in 2.3c that bypasses the table | 2.3c's execution layer receives a `Decision` and has no access to `Input` classification; review rule stated in that sub-phase |
