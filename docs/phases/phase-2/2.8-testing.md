# 2.8 — Testing: matrix, concurrency, invariants, load

**Parent:** [§2.8](../phase-2-lending-checkout.md) · **Depends on:** all above ·
**Unblocks:** 2.9
**Estimate:** 1.5 d · **Risk:** medium — the work that makes the rest trustworthy

## Goal

Each earlier sub-phase carried its own tests. This one adds the tests that
belong to no single sub-phase because they cross all of them: concurrency,
rollback, the invariant roll-call, and load. It is also the sweep that answers
"is any cell of the matrix untested?" with a number rather than an opinion.

## Design notes

**`-race` on every run, not nightly.** Race conditions in the checkout path are
exactly the class of bug that corrupts custody records and cannot be reproduced
from a bug report.

**Concurrency tests are integration tests against real Postgres.** The invariants
under test *are* Postgres features; a mocked database would test the mock.

**The harness matters more than any single test.** Write one reusable helper and
use it everywhere, so adding the twentieth race test costs a minute:

```go
// race runs fns simultaneously, releasing them from one channel, and returns
// their errors in order.
func race(t *testing.T, fns ...func() error) []error
```

### 2.8.4 The invariant roll-call

One test file, `test/integration/invariants_test.go`, with fifteen named
functions, each asserting the invariant from
[03](../../03-domain-model.md#invariants) by its ID — so a reader can grep
`INV-13` and find the code that proves it:

- [ ] INV-1 one open loan per device · INV-2 one active credential per token ·
      INV-3 device status ⟺ open loan · INV-4 revoked never borrows ·
      INV-5 `returned_at` null iff open · INV-6 suspended/archived cannot borrow ·
      INV-7 non-available cannot borrow · INV-8 audit append-only ·
      INV-9 one transaction per device scan · INV-10 no hard delete with history ·
      INV-11 kiosk never creates a user · INV-12 unbound never borrows ·
      INV-13 no overlapping custody · INV-14 paper provenance mandatory ·
      INV-15 `origin` never rewritten
- [ ] INV-2, INV-8 and INV-10 are Phase 1 invariants; assert them here anyway —
      the roll-call is only useful if it is complete

### 2.8.5 Load and shape

- [ ] k6 script at 50× expected peak (≈ 30 concurrent sessions, 500 scans/min)
      against the docker-compose stack, committed under `deploy/loadtest/`
- [ ] Assert p95 scan latency < 100 ms locally and no error rate above 0
- [ ] Watch for the failure modes the numbers exist to catch: an accidental
      O(n²), a missing index, lock waits on the session row, connection-pool
      exhaustion, goroutine growth on the SSE endpoint
- [ ] Record the results in [2.9](2.9-contract-freeze-and-demo.md)'s summary —
      a number nobody wrote down is a number nobody will compare against later

## Exit criteria

- [ ] Every cell of the transition matrix has a passing named test, verified by
      the coverage assertion, not by reading
- [ ] Concurrent-borrow proves exactly one success, repeatedly, under `-race`
- [ ] All fifteen invariants asserted by name in one file
- [ ] Rollback leaves no loan, no status change, no outbox row
- [ ] p95 scan latency < 100 ms locally at 50× peak
- [ ] `task test:integration` runs clean from a cold container in under ~5 min —
      a suite people stop running proves nothing

## Risks

| Risk | Mitigation |
|---|---|
| Flaky concurrency tests get quarantined and then deleted | `race()` helper with a single release channel rather than sleeps; `-count=20` in CI so flakiness surfaces as a failure, not as a rare mystery |
| Suite runtime grows until it is skipped locally | The template-clone `testdb` already avoids per-test migrations; keep new fixtures cheap and prefer unit tests where no invariant is involved |
| Load test written against a stale contract | It drives the same generated TS client / HTTP shapes as the kiosk will |
