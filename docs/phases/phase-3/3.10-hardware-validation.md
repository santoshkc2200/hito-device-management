# 3.10 — Hardware validation ★

**Parent:** [§3.10](../phase-3-kiosk-app.md) · **Depends on:** 3.1b, 3.1c, 3.7 ·
**Unblocks:** 3.12
**Estimate:** 1 d (spread across the phase, not one block) · **Risk:** highest
schedule risk in the phase, and it is external

> **Status, 2026-08-19: the iPad is on hand; the Bluetooth imager is not.**
> The checklist below is therefore split into **10.A — device only**, runnable
> from the first week of the phase, and **10.B — needs the scanner**, blocked on
> arrival. Do all of 10.A early; do not let 10.B's absence delay anything else,
> and do not let it be quietly forgotten either.

## Goal

Prove the thing works on the hardware it will live on: a real Bluetooth imager, a
real iPad, real labels, real corridor lighting, at the real counter. CI cannot do
any of this, which is exactly why it is a named sub-phase with a checklist rather
than a line in someone's head.

## Design notes

**Do not save this for the last week.** The estimate is a day of work, but it must
be *spread* — the iPad is already on the desk, so 3.1c and 3.7 should each be
sanity-checked on it as they land, and 3.1b as soon as the scanner arrives.
The failures this sub-phase finds (a scanner suffix that is Tab not CR, a camera
that will not start without `playsinline`, storage evicted overnight) are cheap on
the day they are introduced and expensive in the final week.

**The scanner is a configuration problem before it is a code problem.** Suffix,
symbologies, sleep timeout and the keyboard-toggle behaviour are all set by
scanning setup barcodes from the manual. Record which ones were used, in the
runbook, with photographs — the next kiosk will need exactly this, and nobody will
remember.

**Fifty labels is the number.** Every device label produced in Phase 1 gets read
first-time, at the angle it actually sits on the shelf. A 96% read rate sounds
fine and means two devices a week that cannot be borrowed.

**A day on battery is a real test.** A kiosk at 3% is a down kiosk, and the
failure mode is silent.

## Work items

### 3.10.A Device only — runnable now

The iPad is available, so none of this waits for anything:

- [ ] Add to Home Screen; standalone mode confirmed (no address bar, no tab bar)
- [ ] Kiosk paired with a code ([3.7](3.7-pwa-and-kiosk-mode.md)); token survives a
      force-quit and an overnight idle
- [ ] Camera permission granted once and persisting in standalone mode
- [ ] Camera fallback decodes a device label at arm's length in corridor lighting
- [ ] Camera fallback works in the dimmest lighting the counter ever sees
- [ ] Guided Access configured with a passcode and verified by trying to escape
- [ ] Auto-Lock = Never; wake lock behaviour observed over an hour
- [ ] Screens legible from one metre; layout intact in both orientations and at
      150% Dynamic Type
- [ ] Audio audible at the counter and not intrusive two beds away
- [ ] A full day on battery, or confirmation the stand keeps it charged
- [ ] Mount and power installed at the counter (the cradle waits for the scanner)

### 3.10.B Needs the Bluetooth imager — blocked until it arrives

- [ ] Imager procured, paired to the iPad (Settings → Bluetooth)
- [ ] Configured via setup barcodes: **suffix = CR**, symbologies QR + Data Matrix
      + Code 128 enabled, others disabled; sleep timeout noted
- [ ] The show/hide-iOS-keyboard toggle barcode located and recorded
- [ ] Scanner pairs and stays paired across an iPad restart
- [ ] Scan works after the scanner has slept 30+ minutes (the first-scan-of-the-
      morning case — verify the wake hint appears and the scan is not lost)
- [ ] Every one of the 50 device labels reads first-time, at shelf angle
- [ ] Curved surfaces (laptop lids, adapter bodies) read reliably
- [ ] Staff card reads through a lanyard sleeve
- [ ] The attendant keypad works with the scanner connected (the reason
      [3.4](3.4-attendant-manual-entry.md) exists)
- [ ] Scanner cradle installed at the counter

Each item is a line in the runbook with a date and a signature, because the whole
checklist is re-run before every release that touches the scan path.

### 3.10.3 Tuning and feedback

- [ ] Inter-key timings recorded from the real scanner via the diagnostics view
      ([3.1b](3.1b-hid-wedge-source.md)); `MAX_INTERVAL_MS` confirmed or adjusted
      **from that data**, with the measured range written into the code comment
- [ ] Any label that fails to read is photographed and fed back to Phase 1's
      labelling (size, quiet zone, material) — a persistent failure is a label
      defect, not a scanner defect
- [ ] Audio verified audible at the counter and not intrusive two beds away
- [ ] Standalone-mode storage checked after an overnight idle: the kiosk token
      survives; a `sessionStorage` session id need not

### 3.10.4 Runbook completion

- [ ] `docs/runbooks/kiosk-ipad-setup.md` corrected against what actually happened
- [ ] Setup barcodes, model numbers and firmware versions recorded
- [ ] A "kiosk is not scanning" triage section: check heartbeat, check scanner
      battery, wake with the trigger, fall back to camera, fall back to the keypad,
      fall back to paper

## Exit criteria

- [ ] Every 10.A item ticked and dated — these gate the phase and have no excuse
- [ ] Every 10.B item ticked and dated, **or** the phase exits with 10.B named as
      outstanding, with the imager's expected date and an owner. What is not
      allowed is exiting with 10.B unmentioned
- [ ] 50/50 labels read first-time; any failure has a photographed cause and a fix
- [ ] The wedge constants reflect measured timings from this scanner
- [ ] Guided Access verified by trying to escape the app
- [ ] Runbook complete enough that a second kiosk can be set up by someone who was
      not present for the first

## Risks

| Risk | Mitigation |
|---|---|
| The imager arrives after the phase should have ended | Known already: 10.A is done early on the iPad that *is* here, 3.1b ships against synthesised timings with its constants marked untuned, and 10.B plus the timing runs in [3.12](3.12-timing-observation-exit.md) are carried explicitly rather than silently skipped |
| The scanner arrives and the wedge constants turn out wrong | 3.1b's diagnostics view records real inter-key timings the day it lands; the constants are one commit, not a redesign |
| Scanner defaults differ from the assumed configuration | Setup barcodes applied and recorded as part of setup, not assumed |
| Labels read badly on curved or reflective surfaces | Fed back to Phase 1 labelling with photographs; the label spec is allowed to change |
| Everything is verified on a desk and fails at the counter | The checklist is run at the counter, in its lighting, with the real mount |
