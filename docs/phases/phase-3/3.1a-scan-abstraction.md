# 3.1a — `ScanSource` and the router

**Parent:** [§3.1](../phase-3-kiosk-app.md) · **Depends on:** 3.0 ·
**Unblocks:** 3.1b, 3.1c, 3.2, 3.4
**Estimate:** 0.5 d · **Risk:** low, but it is the interface every later source is
measured against

## Goal

One interface, one output stream. FR-64 requires that a new input source — an
RFID reader in Phase 6, a Web NFC wrapper on an Android tablet — is added by
implementing an interface and registering it, with **no change to any screen and
no change to the checkout logic**. This sub-phase is where that promise is either
kept or quietly broken.

## Design notes

**The machine must not know what a scanner is.** The router emits `Scan` objects;
`source` is a string it forwards to the server for the audit trail and never
branches on. If any screen or guard ever reads `scan.source` to decide something,
FR-64 is dead and the Phase 6 estimate of "~0 effort" becomes a rewrite.

**Debounce is client comfort, not correctness.** The 1500 ms window stops a stuck
scanner trigger from painting three screens. It cannot be the duplicate guard: a
reload loses it, and two kiosks share nothing. The authoritative duplicate check
is the server's 3-second token-hash comparison
([2.3c](../phase-2/2.3c-scan-orchestration.md)). Both exist; neither is redundant.

**Local format checking saves a round trip, not a decision.** `parseToken` from
`@hdms/domain` rejects garbage before the network — a scanner that reads a
shipping label on a laptop lid should not cost 80 ms and a screen flash. A locally
invalid token emits an `invalid` event the kiosk renders as "That barcode isn't
one of ours", and never reaches the API. Everything that parses is the server's to
judge.

**Sources are cheap to start and stop.** Only one source is "primary" at a time
(the camera exits back to scanner mode after a read), but the wedge listener stays
attached always — a scanner does not announce itself, and the first keystroke of
the morning must not be the one dropped while a source is starting up.

## Work items

### 3.1a.1 Types

- [ ] `packages/scan/src/types.ts` — `ScanSource` and `Scan` exactly as
      [07](../../07-kiosk-app.md) specifies; `raw` is diagnostic only and is never
      sent to the API
- [ ] `ScanEvent` union emitted by the router: `{ kind: 'scan', scan }`,
      `{ kind: 'invalid', raw, reason }` (reason from `TokenParseError`),
      `{ kind: 'duplicate', token }`, `{ kind: 'source-state', id, available }`
- [ ] No React, no api-client, no DOM globals beyond `window`/`navigator` — this
      package stays testable in a bare jsdom environment

### 3.1a.2 `ScanRouter`

- [ ] `register(source)` / `unregister(id)`; `start()` / `stop()` starting each
      registered source that reports `isAvailable()`
- [ ] `subscribe(listener)` returning an unsubscribe function; a single ordered
      stream regardless of how many sources are live
- [ ] 1500 ms debounce keyed on the **normalised token**, not the raw string, so
      `hd-u-…` and `HD-U-…` are one scan
- [ ] Local `parseToken` gate before emission; failures emit `invalid`
- [ ] An injectable `now()` (defaulting to `performance.now`) so every timing test
      is deterministic
- [ ] Errors thrown by a source are caught, reported as `source-state`
      `available: false`, and never propagate into the subscriber

### 3.1a.3 Kiosk-side wiring

- [ ] `useScanRouter()` hook in `apps/kiosk/src/lib/scan.ts` creating the router
      once, registering the sources named in kiosk config `enabled_sources`, and
      cleaning up on unmount
- [ ] The hook is the *only* place the app touches `packages/scan`

## Tests

`packages/scan/src/router.test.ts`, fake timers throughout:
- [ ] `emitsOneScanPerSource`
- [ ] `debouncesRepeatWithin1500ms` and `allowsSameTokenAfterWindow`
- [ ] `debounceIsCaseAndWhitespaceInsensitive`
- [ ] `invalidTokenNeverReachesSubscribersAsScan` — emits `invalid` carrying the
      parser's reason
- [ ] `twoSourcesInterleaveIntoOneOrderedStream`
- [ ] `aThrowingSourceIsIsolated` — the stream survives, the source is marked
      unavailable
- [ ] `stopDetachesEverySource` — no listener left behind after unmount (the leak
      that turns a 12-hour kiosk day into a slow crash)

## Exit criteria

- [ ] A new source can be added by implementing `ScanSource` and registering it,
      with zero changes outside `packages/scan` — demonstrated by a test-only
      `FakeSource` that every later sub-phase's tests reuse
- [ ] Nothing outside the router reads `scan.source` for control flow (grep is
      part of review)
- [ ] `packages/scan` still depends on no React and no api-client

## Risks

| Risk | Mitigation |
|---|---|
| The abstraction leaks and screens start special-casing sources | `FakeSource` exercises every screen path without a real source; a review rule on `scan.source` |
| The client debounce is mistaken for the duplicate guard and the server check is dropped | Both are named in tests, and [3.11](3.11-e2e.md)'s E11 asserts one transaction with the client debounce disabled |
