# 3.3a — The primary-path screens

**Parent:** [§3.3](../phase-3-kiosk-app.md) · **Depends on:** 3.2 ·
**Unblocks:** 3.4, 3.7, 3.9
**Estimate:** 1 d · **Risk:** low technically; this is where the eight-second
budget is won or lost

## Goal

The three screens a borrower actually sees when everything works: `IdleScreen`,
`AwaitingUserScreen`, `AwaitingDeviceScreen`. Zero taps in the normal path, legible
from a metre, and no state where the person has to work out what to do next.

## Design notes

**Every screen answers one question: what do I scan now?** The prompt is the
largest thing on the screen after the outcome. Device details, kiosk name, source
indicators and countdowns are all secondary and must never compete with it.

**The screen must clear itself.** `AwaitingDeviceScreen` shows a person's name,
department and everything they have out. The next person must not see it. That is
the watchdog and the session timeout doing their job ([3.2](3.2-kiosk-state-machine.md)),
and it is worth restating here because it is a property of *this* screen more than
any other.

**Tap-to-return needs a confirmation tap** (FR-30). One stray touch while reaching
past the iPad must not record a return of a device still in someone's bag. The
confirmation is a second tap on the same row, not a modal — modals are the thing
nobody reads.

**Open loans are already in hand.** The scan response carries `openLoans`
([06](../../06-api-contract.md)); the screens render what the machine's context
holds. No screen issues its own query, so there is no second loading state to
design and nothing to go stale.

**Overdue is stated, never punished.** "4 days overdue" with a warning icon,
next to a working RETURN button. A kiosk that scolds is a kiosk people route
around.

## Work items

### 3.3a.1 Screen shell

- [ ] `apps/kiosk/src/screens/` with one file per screen and a `ScreenFrame`
      holding the persistent chrome: kiosk name, scanner-ready indicator, camera
      toggle, countdown slot
- [ ] Screens are pure presentation: props in, callbacks out; the machine is read
      once at the route level and passed down. No screen calls the API
- [ ] The Phase 0 health-check route is deleted, not orphaned — with its e2e
      assertion updated in the same pull request

### 3.3a.2 `IdleScreen`

- [ ] Prompt: "Scan your ID card or a device barcode", ≥ 36 px
- [ ] Scanner-ready indicator fed by `source-state` from
      [3.1b](3.1b-hid-wedge-source.md), with the "press the trigger once to wake
      it" hint after a long idle
- [ ] Camera toggle ([3.1c](3.1c-camera-source.md)) and the kiosk's name and
      support code, small and low-contrast but present — the support code is what a
      person reads out on the phone
- [ ] Nothing person-identifying can render here, ever (asserted by a test)

### 3.3a.3 `AwaitingUserScreen` (device scanned first)

- [ ] Pending device card: asset tag, name, category, status
- [ ] Prompt: "Now scan your ID card"
- [ ] Countdown ring from `expiresAt` (45 s), appearing in the final 8 s
      ([3.6](3.6-feedback.md))
- [ ] A device on loan shows *that it is on loan* without naming the holder —
      the holder is only named after a user identifies themselves and the outcome
      is decided by the server
- [ ] Cancel returns to idle immediately

### 3.3a.4 `AwaitingDeviceScreen` (user scanned first)

- [ ] Greeting with name and department, and the open-loan list as large tappable
      rows (≥ 64 px) with out-date, due-date and an overdue flag
- [ ] RETURN per row, with confirmation tap; the second tap fires
      `returnLoanActor` (FR-30, `return_source = 'manual'`)
- [ ] Prompt: "Scan a device to borrow or return"
- [ ] Done button (closes the session) and the 25 s countdown
- [ ] Empty state — a user with nothing out — reads as normal, not as an error
- [ ] Long lists scroll without the prompt leaving the screen

## Tests

Testing Library, one file per screen:
- [ ] Each screen renders its prompt at the required size and passes `vitest-axe`
- [ ] `idleScreenNeverShowsPersonalData`
- [ ] `awaitingUserShowsDeviceWithoutHolderName`
- [ ] `returnRequiresTwoTaps` and `firstTapAloneFiresNothing`
- [ ] `overdueRowIsFlaggedWithIconAndText` (not colour alone)
- [ ] `openLoansEmptyStateIsNotAnError`
- [ ] `doneClosesTheSession`
- [ ] Touch-target audit: every interactive element ≥ 48 px, primary ≥ 64 px —
      a single test iterating the rendered tree

## Exit criteria

- [ ] All three screens drivable end to end against a live API with simulated
      scans, in both scan orders
- [ ] axe clean on each, at 100% and 150% text scale
- [ ] No screen issues its own API call
- [ ] The Phase 0 health-check page and its e2e assertion are gone
- [ ] A cold render of the idle screen paints in under 200 ms on the iPad
      (measured properly in [3.12](3.12-timing-observation-exit.md), instrumented
      here)

## Risks

| Risk | Mitigation |
|---|---|
| The prompt loses the visual fight with device details | Type scale fixed in [3.9](3.9-visual-design.md); the five-staff observation in 3.12 is the real test |
| A stray touch records a return | Confirmation tap, with a test for the first-tap-alone case |
| The screen keeps a person's name up after they leave | Session timeout plus the unconditional watchdog; E10 covers it |
