## 2. Kiosk Security & Restricted Token Scope

The kiosk authentication model implements **FR-45 & INV-11**:
- Long-lived Bearer tokens issued via `POST /v1/kiosks/pair` using 6-digit one-time codes generated by administrators.
- Restricted scope allowlist: exactly **six** operations permitted:
  1. `POST /v1/sessions`
  2. `GET /v1/sessions/{id}`
  3. `POST /v1/sessions/{id}/scan`
  4. `POST /v1/sessions/{id}/return-loan`
  5. `POST /v1/sessions/{id}/close`
  6. `DELETE /v1/sessions/{id}`
- Zero privilege for user creation, catalog modification, or administrative queries.

## 3. Scan Pipeline & Input Abstractions (`@hdms/scan`)

The scan layer decouples physical input mechanisms from business state:
- **`ScanRouter`:** Single event emitter, enforces 1,500 ms client-side token debounce, formats tokens into canonical `@hdms/scan` payloads.
- **`HidWedgeSource`:** Window capture-phase keydown listener, enforces 35 ms inter-key threshold (`MAX_INTERVAL_MS`), CR suffix validation, suppresses Enter on input fields, synthesizes 5 s inactivity heartbeat for scanner connectivity indicator.
- **`CameraSource`:** `getUserMedia` stream with ZXing WASM fallback, formats locked to `qr_code`, `data_matrix`, `code_128`, 10 FPS downscaled frame processing, torch toggle, and visual viewfinder box.
- **`ManualSource`:** PIN-gated (`8492`) modal with a large-key Crockford Base32 keypad, providing high-contrast touch entry when physical barcodes are damaged or unreadable.

## 4. UI & Visual Design System (`apps/kiosk`)

- **Design System Tokens:** Restrained clinical palette (Accessible Teal/Navy primary, Emerald `#059669` success, Rose `#e11d48` destructive/warning, Slate `#0f172a` neutral).
- **Typography Scale:** Hospital-optimized (Body ≥ 20 px, Subheads ≥ 24 px, Titles ≥ 36 px, Giant Prompts ≥ 48 px).
- **Touch Ergonomics:** Touch targets ≥ 48 px minimum, primary action targets ≥ 64 px tall.
- **Multi-Channel Feedback:**
  - Visual: Entrance animations, tone cards, SVG countdown timer ring (8 s).
  - Audio: Synthesized Web Audio chimes (Ascending major third for borrow, clean fourth for return, minor second double-beep for reject). Respects global mute and `prefers-reduced-motion`.
- **Accessibility:** 100% WCAG 2.2 AA compliant, zero axe violations across all 8 screen states.

## 5. Handoff to Phase 4 (Admin Console)

Phase 4 engineers building the Admin Console should take note of the following integration points established in Phase 3:

1. **Kiosk Device Fleet Management & Pairing (`POST /v1/kiosks/{id}/pairing-code`):**
   - Admin console generates 6-digit one-time pairing codes with 10-minute expiration (`POST /v1/kiosks/{id}/pairing-code`).
   - Admin UI should show pairing state (`unpaired`, `paired`, `last_heartbeat_at`, `kiosk_name`).
2. **Scan Events Telemetry Stream (`GET /v1/events/stream` & `scan_events` audit table):**
   - Every rejected, unbound, or unknown scan produces a structured `scan_events` record.
   - Admin console Paper Backfill UI reads unresolved paper checkout flows and associates unrecognised cards with new users.
3. **Shared Components & Domain Code:**
   - `@hdms/domain`: Share `session-machine.json`, scenario fixtures, and type definitions.
   - `@hdms/api-client`: Auto-generated OpenAPI TypeScript client shared across apps.
