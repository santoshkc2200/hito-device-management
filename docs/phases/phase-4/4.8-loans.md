# 4.8 — Loans

**Parent:** [§4.7](../phase-4-admin-console.md) · **Depends on:** 4.2b ·
**Unblocks:** 4.11b's override tests
**Estimate:** 1.75 d · **Risk:** medium — the override actions are the only place
in the console that rewrites custody

## Goal

The custody record, readable by a human: what is out, what is late, what is
disputed, the full story of any one loan, and three overrides that are always
recorded as overrides.

## Design notes

**Origin belongs in the list, not only in the detail.** Every non-`kiosk` row
carries a badge — `paper`, `admin`, `import`. A record's trustworthiness should
never require a click to discover: a scanned loan and a typed-in loan are
different kinds of evidence, and the person scanning the list is deciding which
ones to chase. This is also the measure of whether paper is receding, which
[4.9a](4.9-reports-and-audit.md) reports over time.

**Overrides never edit the original row.** Force return, write off and
correct-attribution each produce a *new* recorded fact with an actor and a
reason. Correcting a mis-scan by editing the borrower field would erase the
evidence that a mis-scan happened — and mis-scans are exactly what the operational
health report is watching for.

**Every override takes a typed reason and is audited as an override.** Not as a
generic update. The audit viewer's "show me every override last month" is a real
question with a real auditor behind it, and it only works if overrides are
distinguishable from ordinary writes at the query level.

**Disputed records are a first-class view, not a filter nobody finds.** They are
the deliberate output of [4.6d](4.6-paper-backfill.md)'s fourth resolution, and
they are the list somebody eventually reconciles. Give them their own route.

**`[Remind]` copies, it does not send.** Email and SMS are Phase 6. The v1
button puts a prepared message on the clipboard, which is honest about what the
system does and immediately useful in whatever chat app the hospital actually
uses.

## Risks

| Risk | Mitigation |
|---|---|
| Correcting a mis-scan by editing the borrower erases the evidence | Correction is a new linked record; an integration test asserts the original is unchanged |
| Overrides become indistinguishable from ordinary updates in the audit log | Typed as overrides at write time; E15 asserts actor and reason |
| Origin is only visible in the detail, so list rows look equally trustworthy | Badges in the list are a named work item and a component test |
| `[Remind]` is mistaken for a sending feature | Button copy and the toast both say "copied"; sending is Phase 6 |
