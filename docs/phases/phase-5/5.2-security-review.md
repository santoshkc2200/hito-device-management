# 5.2 — Security review

**Parent:** [§5.2](../phase-5-hardening-pilot.md) · **Depends on:** 5.0b ·
**Unblocks:** 5.3, and the go decision
**Estimate:** 4 d · **Risk:** medium — the findings are cheap now and expensive
after the pilot

## Goal

Walk [09](../../09-security-privacy-ops.md)'s threat model item by item, close
what it finds, and turn the properties that must stay true into tests that fail
when they stop being true.

## Design notes

**A review that produces a document is worth less than a review that produces
tests.** Every property below that can be asserted, is: token redaction, kiosk
scope, append-only audit, the security headers. A one-off manual check passes
once and then rots; a test fails in CI the day someone breaks it.

**The kiosk-scope check is a matrix, not a spot check.** FR-45 and INV-11 say the
kiosk token cannot create, modify or list users. The proof is one test per
operation in the contract — and it must fail on an *unclassified* operation, so
that adding an endpoint without deciding its kiosk scope breaks the build.
`internal/platform/auth/kioskscope.go` already carries the allowlist; this
sub-phase makes it exhaustive and asserts the negative case per path.

**Append-only audit is currently a convention.** No migration in the tree issues
a `GRANT` or `REVOKE`; nothing stops an `UPDATE` on `audit_events` beyond
everyone agreeing not to. The parent's exit criterion says the grant must
actually reject — so it becomes a real database grant with a test that attempts
an update and expects a failure.

**Tokens leak through more than logs.** The denylist in the logging middleware
(`IsSensitiveField`, `internal/platform/httpx/middleware.go:45`) covers request
logging. Traces, error response bodies and audit event payloads are three other
places a token can surface, and all four need the same assertion.

**Rate limits that are off in development are untested in development.** The dev
compose sets `HDMS_RATE_LIMIT: "off"` for good reason, which means the limiter's
real behaviour has never been exercised outside its unit test. It is verified
here against the production configuration.

## Risks

| Risk | Mitigation |
|---|---|
| The review becomes a document rather than a control | Every assertable property becomes a CI test |
| A new endpoint later escapes the kiosk-scope rule | The classification suite fails on any unclassified operation |
| CSP is loosened until it passes and never tightened | Written against actual asset loads; the camera and service-worker cases are called out for review |
| Rate limits throttle the offline replay drain | 5.1c's burst is an explicit test case against the production limits |
| Audit rows are edited by a well-meaning operator | A database grant, not a convention, with a test that attempts the edit |
